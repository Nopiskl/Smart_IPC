# 视频、检测与截图

## 当前视频能力

默认 H.264、720×480、目标 25 FPS、3072 kbps、GOP 50。RTSP 默认 `rtsp://<设备IP>:554/live/0`。本版 API 只开放 H.264；后续 H.265 扩展需同步改动编码器和 RTSP codec，并在板端验证后声明能力。

VI 使用 NV12，逐行处理 virtual width / height；OpenCV 中间图像使用 BGR，NPU 预处理转换为 RGB，VENC 输入使用 RGB888。输入模型尺寸从 RKNN 张量属性读取，当前后处理适配单输入、三输出的 INT8 量化 COCO YOLOv5。更换模型时还需核对输出布局、类别数、anchor、颜色顺序及运行时版本。

letterbox 保持宽高比并填充黑边；检测坐标反变换后裁剪到图像范围。NMS 按排序后的真实类别处理，避免跨类别抑制；先保留置信度最高的 1024 个候选框，再执行 NMS，最多输出 128 个检测结果。中文注释说明帧所有权、内存跨度、预处理和释放顺序。

视频配置通过工作线程关闭、重建媒体通道，成功后保存；重新连接 RTSP 客户端。失败时尝试恢复旧配置，恢复失败可在设备状态看到。AI 的阈值和显示开关不主动重建视频通道。

运行中发生取帧、推理或编码错误时，媒体模块关闭通道并记录原因，防止编码超时后复用仍被驱动引用的 DMA 缓冲。Web 服务继续运行；排查原因后重新应用视频配置可尝试恢复媒体。

## 截图

`POST /snapshots` 对最近一次有效视频帧截图，成功后任务结果返回 `snapshot_id/url/mime/size`。媒体不可用、无新鲜帧或编码失败时返回失败任务，不生成空图片。

真实板端使用已有 OpenCV-Mobile 的 `imencode`，其静态库包含 stb JPEG writer，虽然通用 `HAVE_JPEG` 宏未启用，仍支持本项目 JPEG 写入路径。需要在板端实际验证解码、颜色及质量选项。BMP 无压缩，按当前视频分辨率生成。

截图 overlay 独立于视频 overlay，可选择原始画面或叠加检测结果。检测关闭时无检测框。当前截图仅保留内存中的最新一张，重启和下一次成功截图会使旧地址失效；浏览器可下载保存。单张截图大小限制 8 MiB，不提供任意路径写文件接口。

主机媒体模拟器返回 320×240 BMP 测试图，能力接口只声明 BMP；它不验证 JPEG 编码及真实传感器行为。

## 内存与性能

通过 `/device/status` 读取 MemTotal、MemAvailable 及可用时的 CmaTotal/CmaFree。它们是系统公开指标，不能直接代表某个驱动分配池的全部可用空间。

分辨率增加会同时增加 NV12、BGR、显示图像、RGB DMA、编码缓冲及截图临时内存。先以 720×480 建立基线，再逐级提高分辨率，结合当前固件的 CMA 参数评估。目标帧率只是上限，实际帧率取决于采集、推理、编码及网络耗时。

周期截图、定时保存、持久化配额、浏览器连续视频预览可通过现有模块扩展，当前发行版提供手动截图及配置，不声明这些功能已经实现。
